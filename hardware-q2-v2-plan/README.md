## 布线改善与顺序

同网络焊盘之间的最短直线距离，**不是已完成的走线长度**：

| 连接 | 原位置 | 规划位置 |
|---|---:|---:|
| USB → D1，D+ | 11.56 | 1.44 |
| USB → D1，D− | 9.16 | 1.44 |
| CH343P → USB 切换器，D+ | 18.75 | 4.19 |
| CH343P → USB 切换器，D− | 18.14 | 3.59 |
| 1.8 V LDO → DAC 供电脚 | 16.36 | 6.85 |

D1 移近入口后，它到 U17 的受保护支路变长，需要沿下方布线；这是优先缩短未保护段的取舍。不能用上表宣称全板总线长或过孔数量已经下降。

1. GPIO 候选分配已记录在 `pin-assignment.md`；完成裸芯片原理图、封装和实际布线评估后再确定核心朝向。Flash、SD、屏幕 QSPI 分组出线，避免互相穿越。旧模组的引脚号不能直接用于裸芯片。
2. 电源保持充电器/电感/电容及降压器各自局部回路；缩小 SW 铜面积，反馈线避开 SW 和电感。不要为缩短信号线拆散这些局部电路。
3. 优先布晶振、RF、启动 Flash、SD 和屏幕时钟，其次 USB 差分与 I²S；最后处理低速 I²C、控制信号。
4. 继续使用现有六层框架，内层保持连续参考地；具体层叠厚度、阻抗与制造商确认后再定线宽。数字总线从中间通道通过，避免穿过 DAC 晶振、充电泵和耳机模拟输出区域。
5. D1 在背面，USB 入口信号使用短的成对过孔，并提供邻近地回流；不要从未保护的支路绕到其他电路。

## 未完成的电路事项

2026-09-24：新增 `pin-assignment.md`、完整81脚表 `pin-assignment.csv` / `pin-assignment-all-pins.md`、方位图 `pin-assignment-overview.png` 和常量头文件 `q2_v2_pin_plan.h`。这些是原理图设计输入，未修改现有PCB网络。系统总线采用LP I²C，POWER检测须隔离GEK电源域；屏幕SPI2替代引脚组的SDK支持仍待实测。`scripts/plan_pins.py` 仅生成引脚表，不改PCB。

- CORE框内已按用户提供的芯片手册标注8×8本体和−90°候选朝向，仍无电气焊盘。须补裸芯片、40 MHz晶振及匹配、各电源域去耦、射频匹配、启动Flash和下载/复位电路。尺寸、物理引脚及型号核对见 `datasheet-check.md`。
- 原 U10 为 W25Q16JVSSIQ，**16 Mbit = 2 MB**，不能直接等同原 ESP32-S31-WROOM-3-N16R16V 内的 16 MB Flash。其现有位置是外部数据 Flash 候选位置；下一版可结合实际程序容量决定是否替换/合并。原有 C13 的 3.3 V 网络也不能代替尚未设计的 VDD_SPI 供电方案。
- 移除了 U9、FPC2，以及旧 TFT 背光升压的 U16/L4/C42/C55/C56/C57/R40/R41。马达仍使用的 VCC_LCD_BG 相关充电器网络没有删除。第二版原理图要同步这些变化。
- BTB 沿用已讨论的 3.3 V AMOLED 方案和转接板信号映射；TE 作为未接 MCU 的独立预留网络。新接口需增加/核对本地去耦、电源顺序、ESD；这是预接网络，不是电气审核结论。
- BTB 绝对坐标为 `(158.868, 96.847)`。当前 90°对应1脚在顶视图左下，约 `(27.8,30.4)`；90°/270°须通过实物屏幕原生排线折叠确认。原转接板焊接面比主板正面高4.3 mm，XY 对齐不能证明排线可直连。
- RF 预留区尚未检查屏幕金属层的射频影响，不能直接作为 PCB 天线设计或全层禁铜范围。正式核心电路还可能要求调整 CORE 和 Flash 范围。

依据乐鑫官方 [ESP32-S31 原理图检查表](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s31/schematic-checklist.html) 和 [PCB 布局指南](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s31/pcb-layout-design.html) 组织核心预留和布线顺序。RF/时钟及分域供电应以完整参考设计为准。

## 检查范围与交付文件

本次调整55个现有器件，并新增1个BTB候选封装。原生DRC确认焊盘短接0项、封装装配边界重叠0项、跨网络阻焊桥0项；仍有66项其他违规和324项未连接，详见原始报告。保留器件的焊盘网络与源板逐项比较一致。已有模型中，55个移动器件及新增BTB未发现实体碰撞；原FPC1与排线插接处约0.00195 mm³的微小重叠未变化，记录在装配报告中。

- `placement.json`：完整器件记录、源文件校验和、移除项和预留区。
- `connection-distance-check.json`：上述连接距离的计算证据。
- `drc-planning.json`：原生 KiCad DRC，不能作为生产放行报告。规划板无走线，存在未连接项；原导入封装还存在孔类型、丝印、USB 开槽边缘间距和细间距封装与默认0.2 mm规则不相容的问题。没有通过忽略规则来隐藏它们。
- `mechanical-check.json`：将现有STEP模型及8×8×0.9 mm芯片本体占位移入L版装配的碰撞检查。对新增配套电路、屏幕原生排线、公差及整机RF不作验证结论。
- `Q2_V2_Placement_Study.FCStd`：**布局规划装配副本**，不是新的可加工外壳版本。CN2/CN3 高插座及旧屏幕转接板占位已移除；外壳本体没改。
- `V2_Plan.pretty`：当前规划板的本地封装库。3D 模型引用同仓库已有文件，需保留本目录与上级工程的相对路径。参考位号放在 Fab 层用于布局阅读，生产丝印尚未整理。

重建脚本位于 `scripts`，会覆盖本目录生成的规划板及报告；**开始手动布局后不要运行重建脚本，以免覆盖你的修改**。`build_plan.py` 使用 KiCad Python，`check_mechanical.py` 使用 FreeCAD Python，`make_preview.py` 使用带 Pillow 的 Python。
